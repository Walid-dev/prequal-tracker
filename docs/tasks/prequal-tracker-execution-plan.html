The big picture

Gathered requirements, one locked plan, five gates. Each build gate is one feature branch merged into main with a merge commit, so the history shows the branches the assignment asks for. Nothing here touches production, and nothing is pushed: the repo stays on your machine until you push it from your own GitHub account.

Time budget

The budget counts active time, not clock time: the work can pause between gates and pick up later. The core (gates 1 to 3) is planned at 2 hours, the assignment's target. Gate 4 brings it to 2 h 45, which leaves 15 minutes of buffer inside the 3-hour budget. The hard stop is 3 h 30 of active time: whatever state we're in, we stop there and the README says what's left. I log active time per gate in docs/process.md. The gate 5 review is logged on its own line.

The steps

One card per commit. "Files" lists what the commit adds or changes. "Check" is how we know it worked, written so it can fail. At each gate row you read the diffs and the messages, then say GO, and I commit and merge. Every commit ends with the Co-Authored-By: Claude line.

  13. 7
    The triage module
    I

    The AI feature as one self-contained folder. It builds the context, makes one Claude call through the AI SDK with a Zod schema, applies the rules (expired dates, quotes that must exist, an 8,000-character cap, can only lower), and reports tokens, cost, and time. It knows nothing about the database. Mock mode uses stored fixture answers, some with deliberate mistakes so the rules get exercised. A thin service saves each run and never touches request status.

    Files: src/ai/triage/schema.ts · prompt.ts · rules.ts · model.ts · fixtures.ts · triage.ts · rules.test.ts · triage.test.ts · src/domain/triage.ts · src/domain/triage.test.ts

One live call with your key returns a valid result for under $0.02.
